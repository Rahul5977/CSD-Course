CS559 System Design - Lab 10: Simulating database workload patterns with FIO
Rahul Raj (12341680)

Database studied : PostgreSQL 16 (OLTP + reporting use case; 8 KiB pages, WAL, buffered I/O)
Report           : report/RahulRaj_Lab10_FIO_Report.pdf
Task handout     : Lab10_FIO.pdf (last page = database requirement)

Folder layout
-------------
  jobs/        FIO job files, one per case (values like ${QD} are filled in at run time)
                 A_randread_4k.fio       case A  randread  4 KiB  100% read
                 B_randrw70_4k.fio       case B  randrw    4 KiB   70% read
                 C_randrw30_8k.fio       case C  randrw    8 KiB   30% read
                 D_seqread_256k.fio      case D  read    256 KiB  100% read
                 E_wal_8k_fdatasync.fio  case E  (extension) WAL-style 8 KiB appends + fdatasync
  docker/      Dockerfile: Ubuntu 24.04 + fio from apt (fio-3.36)
  scripts/     run_all.sh          host entry point (builds image, runs everything)
               run_in_container.sh experiment loop executed inside the container
               analyze.py          JSON -> CSV summaries, plot data and LaTeX tables (stdlib only)
  results/     raw/*.json          36 main runs: 4 cases x QD {1,8,32} x 3 repetitions
               supp/*.json         QD sweeps, 8 GiB re-run of the full matrix, case E (WAL)
               supp/engine_iouring_A_qd32.error.txt  io_uring blocked by Docker seccomp (EPERM)
               environment.txt     OS, kernel, fio version, filesystem, block device settings
               run_*.log           console logs (all = main run, rest/big = later steps)
               per_run.csv, summary.csv, supp_summary.csv
  report/      report.tex (+ data/, tables/ generated by analyze.py) and the PDF

Fixed parameters (all main runs)
--------------------------------
  ioengine=libaio  direct=1  numjobs=1  size=1g (one shared 1 GiB file)
  ramp_time=5s  runtime=30s  time_based=1  percentile_list=50:95:99:99.9
  Only iodepth (1, 8, 32) changes inside a case; rw/bs/rwmixread change between cases.

How to reproduce
----------------
  Requirements: Docker (tested with Docker Desktop 29.1.3 on macOS 26.6, Apple M4,
  LinuxKit kernel 6.12.54), about 10 GiB free disk, ~45 minutes.

    cd Lab-Task/10.FiOTools
    ./scripts/run_all.sh all          # or: main | supp | big | wal | rest
    python3 -I scripts/analyze.py .   # regenerate CSVs, plot data and tables
    cd report && tectonic report.tex && mv report.pdf RahulRaj_Lab10_FIO_Report.pdf

  Check a single job file without running it:
    docker run --rm -v "$PWD":/lab -e QD=8 -e FIO_FILE=/fio-lab/db-test.bin \
      -e SIZE=1g -e RUNTIME=30 -e RAMP=5 -e ENGINE=libaio csd-fio:lab10 \
      fio --parse-only /lab/jobs/A_randread_4k.fio

Safety
------
  FIO only writes to files inside the dedicated Docker volume "fio-lab" mounted at /fio-lab;
  run_in_container.sh refuses any other target. No raw devices are touched.
  Remove the test data afterwards with:  docker volume rm fio-lab
